# Замер качества извлечения на целых документах (правила + Yargy + LLM)

Дата замера: 2026-10-30, ветка `feat/rpd-extraction`. В отличие от
[замера на фрагментах](extraction-evaluation.md), здесь измерен весь модуль `extract_rpd(..., llm=...)`
на пяти документах целиком: docx → Markdown парсером проекта (`parsing/`) → правила и Yargy →
LLM (`qwen3.6-35b-32k`, `temperature = 0`, как в проде).

## 1. Данные и разметка

Пять документов из `data/РПД и РПП`, выбраны по разнообразию формата до запуска модуля:

| Документ | Тип | Особенность |
|---|---|---|
| С1-3 «Практикум на ЭВМ» (Стандарт) | РПД | 3 семестра, 111 результатов обучения |
| С3 «Теория вероятностей и мат. статистика» | РПД | две траектории, оценивание прозой |
| С5 «DevOps» (ТОП) | РПД | формат ТОП, 1 строка трудоёмкости, шкала баллов |
| С6 «Учебная практика (НИР)» | РПП | компетенции списком, профстандарты, 153 результата |
| С7 «Основы Grid и Cloud вычислений» (Стандарт) | РПД | 10 компетенций, 86 результатов |

Эталон (`gold/*.json`) размечали отдельные агенты по тексту Markdown, не видя ни кода извлечения, ни
его ответов. Разметка не проверена человеком и не размечалась двумя разметчиками, при разметке DevOps таблицы 1.3 и 3.1.4 частично разобраны скриптом. Всего в эталоне ~1035 элементов.

Сопоставление элементов: жадное один-к-одному по нормализованному тексту (код компетенции или
индикатора — точное равенство; текст — совпадение или вхождение). Метрики: микро P/R/F1 по сумме
элементов, «атрибуты» — доля верных `kind`, индикатора, названия у совпавших пар.
Приставка «ПКП-… З-1. Знает» в начале результата обучения при сравнении отбрасывается.

## 3. Разбор ошибок

**Правила**
- Шкалы оценок (`grade_scales`): 0 из 34. В пяти документах извлечено ноль строк: в трёх
  шкала в таблице с шапкой, которую правило не узнаёт, в одном — проза. Это провал полноты.
- Результаты обучения, 6 FP в РПП: подзаголовки групп («Программирование и алгоритмизация»)
  приняты за результаты и одна запись объединена из двух индикаторов в одну.
- Разработчики РПП: 2 из 2 не найдены (причина не разобрана).

**LLM**
- Пререквизиты, 34 FP: в РПП (21) модель принимает за пререквизиты список общих требований к
  навыкам из раздела 1.5; в DevOps (9) и Grid (3) дробит перечень на мелкие сущности
  («HTTP», «DNS», «TLS»), которых нет в эталоне. Часть FP — вопрос гранулярности эталона, а не
  ошибка модели. Атрибут `kind` верен в 85 % пар (дисциплина / область знаний / навык путаются).
- Активные формы, 7 FN: перечни методов («мозговой штурм», «деловые игры», «групповое
  обсуждение») модель сворачивает в одну запись или пропускает; в Grid — 0 из 4. Это тот же
  дефект группировки, что в замере на фрагментах.
- Правила оценивания: помимо правил модель возвращает строки таблиц шкал и описания оценок
  A–E (в строгой метрике это 33 FP). Реальные пропуски (6 FN): организационные формулы
  («максимальная сумма 10 баллов», «промежуточная аттестация складывается из…»).
- Отброшенных цитат нет, невалидных ответов нет (1 предупреждение клиента в Практикуме на ЭВМ).

## 4. Ограничения

- 5 документов, эталон размечен моделью, без проверки человеком и без второго разметчика;
  часть расхождений (гранулярность пререквизитов, считать ли строки шкал правилами оценивания)
  — спорные решения разметки, а не ошибки модуля.
- Один документ — практика; выводы по РПП опираются на один документ.
- Результаты привязаны к модели и промптам на 2026-10-30; один прогон на документ, дисперсия
  не оценивалась.
- Метрики по сопоставлению мягкие по формулировке (вхождение текста), строгих вариантов нет.

## 5. Воспроизведение

Скрипты замера лежат вне репозитория (рабочий каталог сессии): конвертация docx → md
(`parse_document(...).to_markdown()`), прогон `extract_rpd_file(path, llm=OpenAICompatibleClient.from_settings())`
с сохранением JSON, сверка с `gold/*.json`. При необходимости их можно перенести в `src/edu_doc_agent/eval/`.

## 6. Правки после замера (2026-10-30)

По итогам разбора ошибок исправлен `extraction/sections.py::_extract_grade_scale`: правило узнавало
только шкалу «Оценка СПбГУ | ECTS | Критерий» и пропускало раскладку «Критерий | Оценка ECTS |
Оценка за экзамен / при проведении зачёта» (она у трёх из пяти документов). Добавлен юнит-тест.
Промпты не менялись.

Перемер правиловой части (офлайн, ответы LLM прежние):

| Сущность | До | После |
|---|---|---|
| шкалы оценок (TP / FP / FN) | 0 / 0 / 34 | 18 / 0 / 16 |
| правила и Yargy, F1 | 0.98 | **0.99** |
| весь модуль, F1 | 0.94 | **0.96** |

Оставшиеся 16 FN по шкалам — не ECTS-шкалы: 6 описаний оценок прозой (Теория вероятностей) и 10
строк баллов по частям билета (DevOps). Правило их не берёт; нужна ли их выгрузка как `GradeScaleRow`,
решать отдельно.

Решения по спорным местам (чтобы не подгонять метрику под модель):
- **Пререквизиты в РПП (раздел 1.5)** остаются в извлечении: раздел называется «Требования
  подготовленности», в прошлом замере это принято осознанно. Эталон по С6 («0 пререквизитов»)
  спорный, поэтому С6 исключён из подсчёта пререквизитов. F1 пререквизитов по четырём РПД — 0.74
  (20 / 13 / 1).
- **Строки шкал в правилах оценивания LLM** остаются (так размечены gold, holdout и blind2);
  при мягком подсчёте F1 правил 0.74.
- **Гранулярность пререквизитов** (DevOps, Grid): разбиение «основы ОС, сетей, HTTP, DNS, TLS» на
  отдельные пункты — допустимое прочтение, а эталон непоследователен (Linux с деталями в одном
  пункте, «Компьютерные сети» отдельно). Промпт под этот эталон не менялся: без согласованной
  гранулярности правка была бы подгонкой под одного разметчика.

## 7. Правки промптов и перемер LLM (2026-10-30)

Приняты определения (см. раздел 6) и изменён `llm_prompts.py`: перечень технологий и тем в одном
пункте — один пререквизит; названные методы активного обучения — отдельные записи, если у вида
занятий нет своих часов (иначе перечень — содержание занятия); формулы итоговой оценки — правила.
Метрика: строки шкал и описания оценок прозой не считаются ложными срабатываниями правил
оценивания; РПП исключён из подсчёта пререквизитов.

## 8. Повторная проверка issue #30 (2026-11-26)

Проверены исходное [issue #30](https://github.com/citec-spbu/edu-doc-agent/issues/30)
и [комментарий повторного ревью](https://github.com/citec-spbu/edu-doc-agent/issues/30#issuecomment-7016163077).
В ветку PR #45 добавлены исправления трёх оставшихся синтетических контрпримеров:

- Если в DOCX объединён только столбец результатов, область принадлежности результата
  включает компетенции всех строк этого объединения из `Block.spans`. Собственный код
  результата выбирает нужную компетенцию, в том числе расположенную ниже якорной строки.
  Общий результат без кода сохраняет все связи; одинаковые необъединённые ячейки остаются
  отдельными записями. Проверены оба порядка компетенций и объединение обоих столбцов.
- В условиях и следствиях правил оценивания с отрицаниями, сравнениями или числами
  сопоставляется полная упорядоченная последовательность нормализованных слов, операторов
  и числовых значений. Перенос «не» к другому предикату, перестановка границ диапазона
  и обмен порогами разных работ снижают точность атрибутов и отклоняют результат.
  Сохраняется различие знака числа, равенства/неравенства и процента. Регистр, переносы,
  десятичная запятая и эквивалентные записи «не менее»/«не меньше»/`>=` нормализуются.
- Для должностей требуется полная последовательность основ слов (первые пять букв),
  поэтому «директор» не соответствует «директор колледжа». Пропуск дополнения или
  добавление ещё одной должности дают FP и FN. Сохраняется нормализация падежа,
  числа, регистра и пунктуации; прежнее мягкое сопоставление других групп не меняется.

Новые регрессии: `tests/unit/test_issue30_followup.py`. Ранее закрытые требования
проверяются существующими тестами `test_pr22_review_fixes.py` и `test_pr37_review_fixes.py`:

| Требование | Проверка |
| --- | --- |
| Полный пререквизит С4 и оборот «в одной и более» | Точное сравнение состава и полных названий |
| Отрицание в правиле и вымышленное правило с цитатой-фрагментом | Точность атрибутов, FP и отказ `passed()` |
| Бывший holdout использовался при настройке | Набор `REGRESSION`, честная классификация в docstring теста |
| Строка полной цитаты, включая одинаковое начало и перенос | Проверены РПД и LLM-путь характеристики |
| Активные часы по семестрам и альтернативным траекториям | Суммы внутри отдельных траекторий и форм |
| Успешный пустой ответ LLM о пререквизитах | Сверка по `completed_tasks`, отдельно от сбоя вызова |
| Самостоятельные и контактные часы одинакового вида | Раздельная сверка 64/28 ч самостоятельной работы |
| Источники скалярных полей РПД | `sources` для титула, языка, целей, з.е. и кодов |

```bash
uv run --no-sync pytest -q tests/unit/test_issue30_followup.py \
  tests/unit/test_pr22_review_fixes.py tests/unit/test_pr37_review_fixes.py \
  tests/unit/test_llm_gold.py tests/unit/test_characteristic_llm_gold.py
```

Защита метрики правил консервативна: свободный пересказ условия с отрицанием или числами
может быть отклонён даже при сохранении смысла. Сопоставление по основам слов остаётся
приближением и не заменяет проверку смысловой эквивалентности человеком. Исторические
результаты выше получены прежними метриками и не подтверждают прохождение новых критериев.
Промпты и эталоны при этой доработке не менялись; нового онлайн-замера LLM не проводилось.
