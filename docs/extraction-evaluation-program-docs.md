## 3. Как получен эталон

Файлы: `data/evaluation/{plan,ckmv,characteristic,matrix}_gold_full.json` — полный эталон и
`*_gold.json` — небольшой набор, перенесённый вручную (учебный план — 40 строк, ЦКМВ — 3 компетенции,
матрица — 5 строк, характеристика — титул, раздел 1 и часть компетенций).

Конвейер:

1. **docx → Markdown** парсером проекта (`parsing/`, он же используется при обычной работе); xlsx
   матрицы читается экстрактором напрямую.
2. **Полный эталон составлен независимо от экстракторов**, чтобы не мерить код его же ответами:
   - план, ЦКМВ, характеристика — простой построчный разбор сырых строк Markdown по фиксированным
     столбцам, без вызова кода из `extraction/`; контекст (год, семестр, часть, группа, профиль,
     траектория, роль) определён по структурным строкам таблицы; у характеристики группа компетенции
     определяется по префиксу кода, а не по заголовку раздела; титул перенесён вручную;
   - матрица — чтение xlsx стандартной библиотекой (XML напрямую, без `openpyxl`), итоговые строки
     читаются как есть.
3. **Ручной набор** проверен глазами отдельно и сверяется с полным эталоном тестом
   (`test_full_gold_is_consistent_with_hand_labelled_gold` и аналогами): ручные записи обязаны
   совпасть с независимым разбором.
4. **Контрольные счётчики** (число строк, компетенций, единиц матрицы: 226 / 49 / 660) считаются
   отдельным тестом прямо по сырому Markdown и xlsx, без экстрактора.

Эталон составляла модель, человек его целиком не проверял, второго разметчика не было. «Независимо»
означает независимость способа чтения от кода экстрактора, а не независимость от автора.

## 4. Метрики и результаты

Модуль `src/edu_doc_agent/eval/` (`plan_gold.py`, `ckmv_gold.py`, `characteristic_gold.py`,
`matrix_gold.py`, `field_report.py`), общая точка запуска — `eval/program_docs.py`.

**Метрика.** Для каждого элемента эталона ищется парный элемент результата, затем **каждое поле
сравнивается отдельно**. Ненайденный элемент считается ошибкой по всем своим полям. Точность поля =
верно / всего. Это не P/R/F1: лишние элементы результата штрафуются не через FP, а через **контрольные
счётчики** (`count_errors`: число извлечённых строк, компетенций, столбцов и т. д. должно совпасть
с эталоном). Тест проходит, только если нет ненайденных, нет расхождений счётчиков и точность каждого
поля ≥ 0.95. Сопоставление: план — по (код, название, семестр) и порядку; ЦКМВ и характеристика — по
коду и порядку появления; матрица — по номеру строки. Тексты сравниваются нормализованно (регистр,
пробелы, пунктуация).

### 4.5 Сквозная сверка документов

Эталона для неё нет: сверка ищет **расхождения между самими документами**, а не между экстрактором и
правильным ответом. Это перечень для человека, а не измеренная точность.

| Что | Результат |
|---|---|
| Строки матрицы против учебного плана | 118 строк: сопоставлено 111, набор компетенций совпал в 82, **различается в 29**, без пары в плане 7 |
| Сверка кодов компетенций (план — ЦКМВ — характеристика) | коды после нормализации (`УК 1`, `УК–1` → `УК-1`) расхождений не дают; найдено 4 различия в формулировках (ОПК-2, ПКП-МО-1, УКБ-1, УКБ-2; сходство 0.95–0.99, т. е. опечатки и «в т. ч.»/«в том числе») |
| Реквизиты программы (план против характеристики) | расхождений нет |

определению.

### 4.6 Проверка самой метрики

Метрики чувствительны к порче: юнит-тесты (`test_corrupting_one_field_is_detected…` в `test_plan_gold.py`,
`test_ckmv_gold.py`, `test_characteristic_gold.py`, `test_metric_detects_corruptions` в
`test_extraction_matrix.py`) искажают результат «идеального» экстрактора и проверяют, что отчёт падает на нужном поле, а
без искажений — 1.000. Поэтому 1.000 в таблицах — не артефакт метрики, которая ничего не ловит.

Полный прогон 2026-11-08: `pytest` — **1154 passed, 4 skipped, 2 xfailed** (4 пропуска: тесты под
маркером `llm` без флага `--run-llm`).

## 5. Ограничения

- **Один документ каждого типа, одна ОП.** Нет оценки на других шаблонах, числе семестров, шапках
  таблиц, диалектах кодов. Это главное ограничение; 1.000 нельзя переносить на новые ОП.
- Эталон размечен моделью, без полной проверки человеком и без второго разметчика. Ручные наборы
  (40 строк плана, 5 строк матрицы, 3 компетенции ЦКМВ) совпали с независимым разбором полностью.
- Метрика полевая и с контрольными счётчиками, а не P/R/F1: ложные лишние элементы ловятся только
  по счётчикам, не по «P».
- Учебный план: `.xlsx`-версия не разбирается (измерен только docx).
- Характеристика: эталон только на `_corr`; LLM-часть (роли, принципы миссии) не реализована и не
  измерена.
- Экстракторы писались и отлаживались на этих же документах, так что набор для разработки и набор для
  оценки совпадают; независимого holdout, как у LLM-частей РПД, здесь нет.
- На дату замера реальные формулировки лежали в `tests/fixtures/`. 2026-11-16 они перенесены
  в локальный `data/evaluation/`; в Git оставлены синтетические эталоны проверки метрик.

## 6. Воспроизведение

```bash
uv sync
uv run python -m edu_doc_agent.eval.program_docs   # таблицы из раздела 4 для всех документов
uv run pytest tests/unit/test_plan_gold.py tests/unit/test_ckmv_gold.py \
  tests/unit/test_characteristic_gold.py tests/unit/test_extraction_matrix.py
```

Нужен каталог `data/` с архивами (путь можно задать через `DATA_DIR`); без него тесты на реальных
документах пропускаются, а `program_docs` сообщает об этом и завершается.
